## F-1 MEDIUM: todo!() stubs with mandated named params → unused_variables hard errors

**Story:** S-577-3, S-577-4, S-577-5 (Task 11 stub implementations)
**Severity:** MEDIUM
**Status:** FIXED in fix round 12

**Finding:** Task 11 mandates stub implementations using `todo!()` bodies. The ACs also mandate named parameters (e.g., `no_input: bool`, `output: OutputFormat`). These two requirements contradict: under `cargo clippy -D warnings` (CLAUDE.md zero-warnings policy), named parameters in a `todo!()` stub body generate `unused_variables` hard errors — the gate is unsatisfiable as written. Adding `#[allow(unused_variables)]` is forbidden by CLAUDE.md ("No lint suppression without refactoring").

**Fix applied (round 12):** Underscore-prefix stub convention (`_no_input`, `_output`, `_client`, etc.) across S-577-3, S-577-4, S-577-5 Task 11 stub signatures. S-577-4 keeps `_no_input` prefixed at stub stage; S-577-5 un-prefixes at the gate (Task 14/15 integration, where the param is consumed). Lifecycle notes added to clarify the prefix→un-prefix transition per story.
