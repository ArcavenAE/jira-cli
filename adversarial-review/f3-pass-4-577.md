### MEDIUM

**F-1 MEDIUM — BC-3.5.009 body-required guard unowned in its owning story**
The body-required guard (BC-3.5.009 — exit 64 when body is empty after trim) was referenced in multiple stories but not formally owned by any AC that tests the guard in isolation. `S-577-4` was the natural owner (edit path), but had no pipeline branch for the empty-body case. **Fix:** pipeline branch added to `S-577-4` for the empty-body exit; `AC-011` added (guard fires before ADF conversion, exits 64 with message). S-577-4 now has 11 ACs.

**F-2 MEDIUM — AC-010 404 fixture non-discriminating (body text was preamble substring)**
`S-577-4` AC-010 used a 404 error fixture whose body text was a generic preamble substring. Any response body containing that substring would pass — including accidental 404s from unrelated endpoints. VP-577-024 requires the fixture to discriminate the exact Jira "issue does not exist" 404 shape. **Fix:** fixture body text replaced with VP-577-024 discriminating text (Jira-specific error message pattern that does not appear in unrelated 404s).

### LOW

**F-3 LOW — `S-577-6` "both-encoded" claim contradicted by `get_comment` + EC-3.5.002-2**
`S-577-6` PSI stated that both the issue key and comment ID should be URL-encoded in the request path. EC-3.5.002-2 and the `get_comment` implementation only encode the issue key; the comment ID is a numeric string that does not require encoding. The "both-encoded" claim would cause implementers to over-encode. **Fix:** claim corrected to key-only encoding; comment-ID encoding note removed.

**F-4 LOW — BC-3.5.011 parity: `S-577-1` authors its `conflicts_with` but BC not in frontmatter**
`S-577-1` body introduced `conflicts_with_all` and mentioned BC-3.5.011 in a comment, but BC-3.5.011 was absent from the frontmatter `bcs:` field. Incomplete traceability. **Fix:** BC-3.5.011 added to `S-577-1` frontmatter as scoped entry with pre-satisfaction note (the `conflicts_with_all` pattern is introduced here and satisfies the BC before any test is written).

**F-5 LOW — Timestamp reformat instruction vs ISO-8601 mandate**
`S-577-6` PSI included an instruction to reformat the API-returned timestamp into a human-friendly display string. EC-3.5.002-3 mandates rendering the timestamp as-is (ISO-8601 raw). The reformat instruction contradicts the render-raw rule. **Fix:** PSI instruction replaced with render-raw rule; reformat removed from AC guidance.
