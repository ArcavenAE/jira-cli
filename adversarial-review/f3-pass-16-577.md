## F-1 MEDIUM: VP-577-018/019 parse-success tests framed as subprocess — Red→Green trap

**Story:** S-577-1
**Severity:** MEDIUM
**Status:** FIXED in fix round 17

**Finding:** VP-577-018 and VP-577-019 were framed as wiremock-free subprocess "exit NOT 2" assertions. This is a Red→Green trap: a subprocess invocation passes clap argument parsing, then enters the handler, which calls the Jira API, which returns NotAuthenticated in the XDG test environment — the process exits 2 (exit code for auth errors), causing the assertion `exit NOT 2` to fail. The VP was written as a parse-success proof but the mechanism guarantees parse-failure on the subprocess path.

The spec states "no network call required" for these VPs — the intent is pure clap parse validation, not handler execution.

**Fix applied (round 17):**
- Re-specified as in-process `Cli::try_parse_from(...).is_ok()` + destructure assertions (sibling-test convention matching VP-577-016/017 and other parse-VPs in the bundle)
- Purity table split: hint-VPs remain subprocess; parse-success VPs explicitly marked pure-core (`Cli::try_parse_from`)
- EC-007/EC-008 aligned with the updated mechanism
