## F-1 MEDIUM: Round-18 carve-out mis-assigned VP-018/019 to runtime red→green loop

**Story:** S-577-1
**Severity:** MEDIUM
**Status:** FIXED in fix round 19

**Finding:** Round-18's fix re-specified VP-018/019 as in-process `Cli::try_parse_from` tests, but the updated story placed them in the same runtime red→green testing loop as the subprocess tests. In-process tests that reference a not-yet-existing type (the new `Comment` enum variant) are compile errors — they cannot be placed in a "run tests, observe red" loop because the binary does not compile at that point.

The correct structure is a 4+2 split:
- **Task 1 (4 subprocess tests):** Existing subprocess tests that verify the old flat `comment` dispatch path — these run before the atomic breaking change, fail with the specific migration hint output, and serve as the runtime red proof
- **VP-018/019 (2 in-process tests):** Authored in Task 3b, riding the atomic compile gate — they are written during the compile-failure phase and only become runnable after all match arms are updated

**Fix applied (round 19):** 4+2 split with verified per-test pre-change failure modes for the 4 subprocess tests; VP-018/019 explicitly placed in Task 3b with the atomic compile gate.
