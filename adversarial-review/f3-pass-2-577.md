## Findings

### HIGH

**H1 — Seam-defeating `refuse_noninteractive` reuse (4 ACs unsatisfiable)**
Multiple stories (`S-577-3`, `S-577-5`) reused `refuse_noninteractive()` from an existing handler for the `--public` confirmation gate. This helper checks whether stdin is a TTY AND `--no-input` is set — but the `--public` gate should fire on `--no-input` alone (the TTY state is irrelevant when the script explicitly opts out). Using `refuse_noninteractive` would cause `--no-input --public` to pass through on a TTY, defeating the DEC-169 F-A4 ruling. 4 ACs were unsatisfiable as written. **Fix:** replaced with `no_input-alone` gate pattern; added Rule 8 warning in both story files documenting the seam so future implementers don't revert to `refuse_noninteractive`.

**H2 — EC-3.5.009-2/3/4 orphaned between story file-ownership boundaries**
EC-3.5.009 sub-clauses 2/3/4 (error-handling paths for comment-add: 401, 403, 404) were not owned by any story — they fell in the gap between `S-577-1` (which owned the main flow) and `S-577-3/4` (which owned edit/delete). An adversary could inject a non-compilable stub and pass all ACs without covering these error paths. **Fix:** `S-577-1` gains `AC-012` (clap sketch + error dispatch table covering sub-clauses 2/3/4); S-577-1 now has 12 ACs.

**H3 — `S-577-5` VP scramble (VP-577-010/017 wrong targets, VP-577-025/028 orphaned)**
`S-577-5` ACs cited VP-577-010 (view AC, not edit) and VP-577-017 (wrong property) — both wrong targets. VP-577-025 and VP-577-028 were listed in the story preamble but not cited by any AC, leaving them orphaned. **Fix:** VP citations re-mapped — 010 replaced with correct visibility-property VP, 017 corrected, 025/028 bound to specific ACs.

**H4 — `S-577-6` VP-021 variant numbering all off + VP-016 mis-anchored + VP-007 double-used**
`S-577-6` had all four VP-021 variant sub-IDs wrong (shifted by one), VP-016 anchored to a delete-path AC instead of view, and VP-007 used twice across two unrelated ACs. **Fix:** VP-021 variants renumbered to correct spec mapping; VP-016 re-anchored; VP-007 replaced on the second use with the correct VP; `AC-009` updated to dual assertion covering both variants.

**H5 — Render guidance (comfy-table/padding) would fail 5 byte-pinned VP variants**
`S-577-6` contained AC guidance to use comfy-table and padding helpers for comment list rendering. Five VP-021 variants pin exact byte output — comfy-table adds column padding that would break those assertions. **Fix:** render guidance updated to single-space rule (one space between columns); comfy-table explicitly prohibited for this output surface; prohibition documented in AC.

### MEDIUM

**M2 — Hint-text paraphrase instead of spec verbatim**
`S-577-5` paraphrased the user-facing hint text for the `--public` confirmation prompt. The spec (BC-3.5.008) pins verbatim text. Paraphrase would fail the byte-comparison AC. **Fix:** hint text replaced with spec-verbatim string.

**M3 — `AC-007`/`AC-009` under-assertion (single variant, missing dual pin)**
`S-577-6` AC-007 and AC-009 each asserted only one VP variant instead of the required dual assertion (both the positive and negative case). **Fix:** dual pins added; second variant added to AC-009.

**M4 — Rung-c identifier fallback missing in pseudocode**
`S-577-6` pseudocode for the comment-id resolution chain omitted the fallback for rung-c (numeric string as direct ID bypass). **Fix:** fallback added to pseudocode + sub-case documented covering the all-ASCII-digit input path (mirrors `jr requesttype` numeric-bypass convention).

### LOW
