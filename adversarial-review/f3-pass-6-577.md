## Findings

### HIGH

**H-1 HIGH — `S-577-6` invented "Body:" label (beyond-spec; made AC-001/006 mutually unsatisfiable with AC-011's byte pin)**
`S-577-6` introduced a `"Body:"` label prefix in the comment view output format. This label does not appear in the spec (BC-3.5.010 pins the exact output shape — no "Body:" label). The invented label created a mutual unsatisfiability: AC-001 and AC-006 pinned the no-label format, while AC-011 (added in pass-5) pinned the "Body:" variant — both ACs could not be satisfied simultaneously by any single implementation. **Fix:** "Body:" label removed from all occurrences across S-577-6; output format re-characterized as 6-field header labels + unlabeled body block, consistent with spec. AC-011 byte pin updated to match.

### MEDIUM

**M-1 MEDIUM — `no_input` threading unassigned across dispatch boundary**
The `no_input: bool` flag must be threaded from the top-level `CommentArgs` dispatch down into `handle_edit` and `handle_delete` (which gate interactive prompts) but NOT into `handle_view` and `handle_add` (which have no interactive prompts). This threading obligation was not assigned to any story task. Without explicit Task pins, an implementer could omit the threading or thread it to the wrong handlers. **Fix:** `S-577-1` Task 3 gains signature pins for all four handlers (delete/edit signatures include `no_input`; view/add without); Task 4 gains dispatch threading pin; PSI cross-notes added to S-577-3 and S-577-5 referencing the threading contract.

**M-2 MEDIUM — `S-577-5` under-capture (changed_fields exact key-set unasserted; VP-010 discriminator dropped; handler-tier b/c clauses missing)**
Three gaps in S-577-5 AC coverage: (1) `changed_fields` JSON output key-set was described but never byte-asserted against VP-577-010; (2) the VP-577-010 discriminator (the field that distinguishes a successful edit from a no-op) was dropped in a prior fix round; (3) handler-tier b/c clauses (the edit-path branches for `--internal` and `--public` with explicit flags) had no AC coverage. **Fix:** 5 AC extensions across S-577-5 — exact `changed_fields` key-set assertion, VP-010 discriminator restored, handler-tier b/c clause ACs added.

### LOW

**L-1 LOW — `pub(super)` mislabel on comment CRUD helpers**
`S-577-1` PSI section labelled the comment CRUD helper functions as `pub(super)` (module-private to the parent). These helpers must be `pub` (crate-visible) because they are called from `cli/issue/comments.rs` across the module boundary. **Fix:** visibility corrected to plain `pub`; rationale cited (cross-module call from `cli/issue/comments.rs`).
