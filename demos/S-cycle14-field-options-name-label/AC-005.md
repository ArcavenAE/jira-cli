# AC-005 — Rendering contract for a `None` label is byte-for-byte UNCHANGED (COUNT-NEUTRAL)

**Traces to:** BC-X.14.003 UPDATED blockquote (cross-reference only, count-neutral).

## What this demonstrates

The rendering contract for a `None` label (`"(unnamed)"` in table output, `null` in `--output
json`) is unchanged by this story — only the upstream normalizer (AC-001) now produces *fewer*
`None` labels for system fields. This AC does not add a new test/recording of its own; it is
observed via `AC-001-neither-present-unnamed`'s own recording (the "Legacy Probe" `{"id": "99"}`
entry, which still has no `value` and no `name`, and therefore still renders `"(unnamed)"`/
`null`), and by regression tests already covering `render_option_rows`
(`src/cli/field.rs::test_bc_x_14_003_render_option_rows_degenerate_glyphs`,
`test_bc_x_14_003_field_option_json_serializes_none_as_null_not_omitted`) which this story does
not touch.

## Recordings

- See `AC-001-neither-present-unnamed.{tape,gif,webm}` (shared with AC-001) — the same
  degenerate-entry recording serves as this AC's evidence, since AC-005's own claim is that
  nothing about that rendering changed.

## Result

`"(unnamed)"`/`null` still render for a genuinely label-less entry, identically to before this
story.

## Verdict

**PASS (cross-reference, count-neutral)** — no new behavior; existing rendering contract
confirmed unchanged via the shared AC-001 recording.
