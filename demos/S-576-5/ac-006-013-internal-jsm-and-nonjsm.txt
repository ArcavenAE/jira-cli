--- AC-013 / test_bc_3_9_004_internal_on_non_jsm_silent_noop_oq9 ---

Scenario:
  Invocation: jr issue attachment upload DEV-1 nonjsm.txt --internal
  DEV-1 is a non-JSM issue (projectTypeKey = "software").
  OQ-9 ruling: --internal on non-JSM is a SILENT NO-OP — falls through to the regular
  platform POST (/rest/api/3/issue/{key}/attachments). No error, no warning, no mention of --internal.

Wire sequence simulated:
  GET /rest/api/3/issue/DEV-1                          → 200 (Step 0: project.key = "DEV")
  GET /rest/api/3/project/DEV                          → 200 (software project, not service_desk)
  POST /rest/api/3/issue/DEV-1/attachments             → 200 (platform upload, regular path)
  (NO servicedeskapi calls)

Assertions verified:
  - exit code == 0  (no error on --internal with non-JSM)
  - stderr does NOT contain "--internal"  (silent no-op, no mention of the flag)
  - zero calls to servicedeskapi attachTemporaryFile or request/.*/attachment endpoint
    (verified via server.received_requests() filter on "servicedeskapi" paths)

This is asymmetric from --public: --public on non-JSM exits 64 (customer-visible upload
requires servicedeskapi); --internal on non-JSM is silent because platform upload is already
agent-internal by default.
