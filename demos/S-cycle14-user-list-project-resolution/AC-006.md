# AC-006 — empty string `--project ""` passes through (D-380)

**Traces to:** BC-X.7.002 EC-X.7.002-6, D-380.

## What this demonstrates

`--project ""` (empty string), whether supplied locally or globally, passes through as
`Some(String::new())` and resolves the project key to the empty string **without** consulting the
configured default — settled behavior, human-confirmed (D-380), matching `jr queue`/
`jr requesttype`'s existing empty-string pass-through. Jira's response (not `jr`) decides whether
an empty `projectKeys=` is itself an error.

This is a bonus recording beyond the task's minimum eight scenarios, included because it is the
one AC (besides the doc/config-only AC-010/AC-011) not otherwise covered by scenarios (1)-(8), and
it is cheap to demonstrate with the same mock server.

## Recording

- `AC-006-empty-string-passthrough.tape` / `.gif` / `.webm`

Command demonstrated:

```
jr user list --project "" --no-input
```

Environment: `fixtures/config-default-project.toml` — the active profile **has** a configured
default (`project = "PAG"`), deliberately, so the recording can show the empty string does NOT
fall back to it.

## Result

Exit 0. Table output shows `[project=]` (empty) in every row — the mock server received
`projectKeys=` (empty), not `projectKeys=PAG`, confirming the empty string was NOT overridden by
the configured default.

## Verdict

**PASS** — empty-string `--project` passes through verbatim and does not consult the configured
default.
