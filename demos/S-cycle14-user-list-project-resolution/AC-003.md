# AC-003 — configured default fallback (`resolve_user_list_project`)

**Traces to:** BC-X.7.002 Postcondition 3, EC-X.7.002-3, EC-X.7.002-5, EC-X.7.002-7; Fix step 4
(the pure `resolve_user_list_project` resolver).

## What this demonstrates

When both local and global `--project` are absent, `resolve_user_list_project(cli_project, config)`
falls back to `Config::project_key`'s existing chain: `.jr.toml` project first, then the active
profile's configured `project` default. Two sub-cells are recorded:

1. **`.jr.toml`-only** — no configured profile default, but the cwd has a `.jr.toml` with
   `project = "BAR"`.
2. **Non-default `--profile`'s own default** (this sub-cell doubles as AC-009's demonstration of
   `&Config` threading without reload — see `AC-009.md`) — a two-profile config where `default`
   has no project but `alt` has `project = "BAZ"`, invoked via `jr --profile alt user list`.

## Recordings

- `AC-003-jrtoml-default.tape` / `.gif` / `.webm` — sub-cell 1 (`.jr.toml`)

  ```
  jr user list --no-input
  ```

  Environment: no configured profile default, cwd's `.jr.toml` contains `project = "BAR"`
  (written by `setup.sh`'s optional 3rd argument). The tape first `cat`s `.jr.toml` on screen so
  the viewer can see the source of the resolved value.

- `AC-003-AC-009-profile-default.tape` / `.gif` / `.webm` — sub-cell 2 (profile default)

  ```
  jr --profile alt user list --no-input
  ```

  Environment: `fixtures/config-alt-profile.toml` (`default` profile has no project; `alt` has
  `project = "BAZ"`), no `.jr.toml` ancestor.

## Results

Both exit 0. The `.jr.toml` recording's table shows `[project=BAR]`; the profile-default
recording's table shows `[project=BAZ]` — each confirming the resolved key traveled all the way
to the outbound `projectKeys=` query parameter without any local/global flag being supplied.

## Verdict

**PASS** — both configured-default fallback paths (`.jr.toml` and a non-default profile) resolve
correctly with zero local/global flags.
