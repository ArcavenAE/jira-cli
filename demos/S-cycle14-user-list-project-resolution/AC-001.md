# AC-001 — local `--project` flag alone resolves

**Traces to:** BC-X.7.002 Fix step 1, Postcondition 1 (clap-required `String` -> `Option<String>`,
`short = 'p'` unchanged, local flag resolves to `Some(value)` regardless of global/configured
default presence).

## What this demonstrates

`UserCommand::List.project` is now `Option<String>` instead of clap-REQUIRED `String`. Supplying
only the local `--project` flag (no global flag, no configured default anywhere) resolves and
succeeds — this was already working pre-story (the local flag alone satisfied the old required
field), but the type change is what makes the *other* resolution paths (AC-002, AC-003) possible
without breaking this one.

The story's own inline `Cli::try_parse_from` unit test
(`src/cli/mod.rs::tests::test_bc_x_7_002_user_list_project_clap_propagation`) is the authoritative
parser-level proof for all four base argv cells plus the two `-p` short-alias cells; this
recording is the end-to-end, real-binary corroboration of the local-flag base case.

## Recording

- `AC-001-local-project.tape` / `.gif` / `.webm`

```
jr user list --project FOO --no-input
```

Exit 0. Table output lists two synthetic users, with the mock server echoing
`projectKeys=FOO` back into each display name (`[project=FOO]`), visually confirming the
resolved key sent on the wire.

## Verdict

**PASS** — local `--project` resolves and succeeds with no configured default present.
