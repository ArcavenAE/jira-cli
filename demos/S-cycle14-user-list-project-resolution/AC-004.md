# AC-004 — no project resolvable → exit 64, pinned message, zero HTTP

**Traces to:** BC-X.7.002 Postcondition 4, EC-X.7.002-4, Behavior, Preconditions.

## What this demonstrates

When none of {local `--project`, global `--project`, configured default} resolve a project key,
`handle_list` exits 64 (`JrError::UserError`) with the byte-identical pinned message:

```
No project configured. Run "jr init" or pass --project. Run "jr project list" to see available projects.
```

...**before any HTTP call**. Both output modes are recorded to show the message survives the
JSON-render invariant (#526) unchanged in substance.

## Recordings

- `AC-004-exit64-table.tape` / `.gif` / `.webm` — human/table mode

  ```
  jr user list --no-input
  echo EXIT_CODE=$?
  ```

- `AC-004-exit64-json.tape` / `.gif` / `.webm` — `--output json` mode

  ```
  jr --output json user list --no-input
  echo EXIT_CODE=$?
  ```

Environment (both): `fixtures/config-no-project.toml` (no profile default), no `.jr.toml`
ancestor — none of the three resolution sources can resolve a project. `JR_BASE_URL` still
points at the reachable mock server for both recordings; the mock server's own logging is
silenced, but its `expect`-less handler would answer any request it received — the fact that the
table shows no user rows (an immediate error) is the observable evidence no request was sent, and
`search_assignable_users_by_project[_all]` is only ever called after the resolver returns
`Some(_)`, per `src/cli/user.rs::handle_list`.

## Results

- **Table mode:** stderr `Error: No project configured. Run "jr init" or pass --project. Run "jr project list" to see available projects.`, `EXIT_CODE=64`.
- **JSON mode:** stdout `{"code":64,"error":"No project configured. Run \"jr init\" or pass --project. Run \"jr project list\" to see available projects."}` (pretty-printed per the #526 JSON render invariant), `EXIT_CODE=64`.

Both messages are byte-identical to BC-X.7.002 Postcondition 4's pinned text.

## Verdict

**PASS** — both output modes exit 64 with the exact pinned message; zero HTTP call observed by
construction (no user rows/table ever rendered before the error).
