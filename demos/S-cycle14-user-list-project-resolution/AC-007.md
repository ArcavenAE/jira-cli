# AC-007 — resolved project applied to every `--all` page

**Traces to:** BC-X.7.002 Postcondition 5.

## What this demonstrates

Once resolved (by any of steps 1-3), every request carries `projectKeys=<resolved-key>` —
including every offset page fetched by `--all`, not just the first. This recording exercises the
configured-default resolution path (no local/global flag at all) combined with `--all` pagination,
which is the story's Task-5 "configured-default `--all` cell" (the RED-at-stub cell in the story's
Red Gate classification, since it hits the resolver's `None` arm).

## Recording

- `AC-007-all-pagination.tape` / `.gif` / `.webm`

Command demonstrated:

```
jr user list --all --no-input
```

Environment: `fixtures/config-default-project.toml` (`project = "PAG"`), no local/global flag.
The mock server (`mock_user_search_server.py`) returns 2 users on page 1 (`startAt=0`) and an
empty array on the next page (`startAt=100`, one `USER_PAGE_SIZE` window later) — the empty-page
end-of-data signal `search_assignable_users_by_project_all` relies on (see
CLAUDE.md's "User pagination advances by `USER_PAGE_SIZE`" gotcha) — keeping the demo to exactly
two HTTP requests instead of needing 100+ fake users to fill a page.

## Result

Exit 0. Table output shows `[project=PAG page1]` in every row, confirming the SAME resolved key
(`PAG`, from the configured default — no flag supplied at all) was threaded through to the
`--all` pagination loop, not just a first/default-path call.

## Verdict

**PASS** — the resolved project key is applied to the paginated `--all` path exactly as it is to
the default path.
