# AC-008 — Pre-flight ordering: `-q` validation runs strictly before `resolve_body`'s blocking stdin read

**Traces to:** BC-X.16.002 Postcondition 1, D-188 pre-flight convention; EC-X.16.002-4.

## What this demonstrates

Every malformed `--query-param` value is caught BEFORE any query string is assembled and BEFORE
`resolve_body` runs (which may block reading stdin for `-d @-`). `jr api /x -X POST -d @- -q bad`
must exit 64 immediately regardless of stdin's state — including a pipe held open by a producer
that never writes and never closes, which is the one state under which a buggy ordering (reading
stdin before validating `-q`) would actually hang instead of merely returning early.

## Recording

- `AC-008-preflight-before-blocking-stdin.tape` / `.gif` / `.webm` — a background subshell opens a
  FIFO for writing and never writes to it or closes it (`exec 3>fifo; sleep 30`), simulating a
  held-open stdin producer. `time timeout 5 jr api /rest/x -X POST -d @- -q bad < fifo` returns
  in a fraction of a second with exit 64 — NOT after the 5s `timeout` safety net fires — proving
  `-q` validation (Postcondition 1) runs strictly before `resolve_body`'s blocking `@-` read.

## Result

Exit 64 with the M1 message, returning near-instantly (visible via the `time` builtin's real
elapsed output), not after the 5-second `timeout` ceiling.

## Verdict

**PASS**.
