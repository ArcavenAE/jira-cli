# AC-007 — All-or-nothing; first-malformed-in-flag-order is reported (Postcondition 3, Invariant 3)

**Traces to:** BC-X.16.002 Postcondition 3, Invariant 3; EC-X.16.002-3.

## What this demonstrates

Two `-q` flags where the SECOND is malformed: the WHOLE invocation fails before any HTTP call —
the first, well-formed pair is never sent — and `--query-param` values are validated via a
`.collect::<Result<Vec<_>>>()`-style short-circuiting iteration in FLAG ORDER, so the error
reported is the FIRST malformed value encountered in that order (which, with only one malformed
flag present, is that flag itself).

## Recording

- `AC-007-all-or-nothing.tape` / `.gif` / `.webm` — `jr api /rest/x -q good=1 -q bad; echo
  "exit=$?"` → `exit=64`, M1 message naming `bad`; `wc -l` on the mock's request log (truncated
  to empty just before this recording) stays `0` — the well-formed `good=1` pair, despite coming
  first in flag order, is never sent to the server.

## Result

Exit 64, zero HTTP calls despite one well-formed pair being present.

## Verdict

**PASS**.
