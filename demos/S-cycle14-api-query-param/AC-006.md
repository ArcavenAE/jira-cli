# AC-006 — `parse_query_param` M2 (empty NAME), distinct message, `--output json` envelope

**Traces to:** BC-X.16.002 Behavior, Postcondition 2; EC-X.16.002-2.

## What this demonstrates

`--query-param =v` (empty NAME, non-empty VALUE) is REJECTED — a DISTINCT client-side failure
from M1 (missing `=` entirely), even though an empty VALUE (`k=`) is allowed. Exit 64,
`JrError::UserError`, message `"--query-param NAME cannot be empty (got: {raw}) — use
NAME=VALUE, e.g. -q maxResults=50"`. The two messages (M1's "must be in NAME=VALUE format" vs.
M2's "NAME cannot be empty") each contain a substring absent from the other, so they are
distinguishable by substring match alone.
