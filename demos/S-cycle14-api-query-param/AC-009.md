# AC-009 — clap's own attached-value parsing / argument-level edge cases (EC-X.16.002-5..10)

**Traces to:** BC-X.16.002 Edge Cases EC-X.16.002-5/6/7/8/9/10 (EC-X.16.002-11, non-UTF-8, is (U)
— inherited clap behavior, not independently demonstrated here; same treatment as EC-X.14.001-14).

## What this demonstrates

How clap's own short-/long-flag attached-value parsing delivers `raw` to `parse_query_param`
before BC-X.16.002's M1/M2 taxonomy ever runs, plus the boundary where a malformed invocation
fails at the CLAP level (exit 2) rather than reaching `parse_query_param` at all (exit 64).

## Recordings

- `AC-009-attached-equals-forms.tape` — `-q=v` (one `=`; clap strips exactly one leading `=`,
  delivering `raw="v"` → M1, got: v); `-q==v` (two `=`; only the first `=` is stripped, delivering
  `raw="=v"` → M2, got: =v); `--query-param==v` (long-flag attached form; BYTE-IDENTICAL outcome
  to `-q==v` even though the long-flag parser has no separate strip step of its own).
- `AC-009-clap-level-errors.tape` — `-q -x=1` (no `allow_hyphen_values`, so clap treats `-x` as an
  unrecognized new flag → exit 2, never reaching `parse_query_param`); `-q` as the LAST argv token
  (a genuinely MISSING value → clap's own `ErrorKind::InvalidValue` → exit 2, not 64).
- `AC-009-empty-raw-value-forms.tape` — three distinct forms (`-q ''`, `-q=`, `--query-param=`)
  all deliver `raw=""` (a PROVIDED empty value, not a missing one) and all classify as M1 (an
  empty string has no `=` to split on) — never M2, since the empty-NAME check is only reachable
  once a `=` has actually been found.

## Result

All three recordings exit with the documented codes (64 for the M1/M2 cases, 2 for the clap-level
cases).

## Verdict

**PASS**.
