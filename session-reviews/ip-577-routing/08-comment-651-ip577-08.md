## SOH-COMMENT-CRUD-1 cycle datapoint — fallback-to-comment as standard path (IP-577-08)

**Source:** jira-cli SOH-COMMENT-CRUD-1 session review 2026-07-15 (IP-577-08)

---

### New instance and proposed standard

**Instance (PG-F4-9, wave-C, PR #617):**

pr-manager completed a fresh-eyes review of PR #617 (S-577-4 comment-edit core) and verbally declared the review complete in agent context — but did not post a review evidence comment to the PR thread. The `validate-pr-review-posted` hook found no evidence of a posted review and could not verify the verdict. The gap was caught when the user asked directly: "did we review 617?"

The review verdict (a COMMENTED verdict from a same-account reviewer, equivalent to APPROVE per DEC-173) existed only in the agent's context window and was therefore unverifiable by any external check.

**Proposed change: fallback-to-comment is now STANDARD, not optional.**

When the `validate-pr-review-posted` hook cannot verify a posted review comment (whether because the reviewer is on the same account as the PR author, or because `gh pr review --comment` was used, or for any other structural reason), pr-manager MUST post the review summary as a `gh pr comment` before declaring review-complete:

```bash
gh pr comment <PR-number> --body "## Fresh-eyes review verdict: APPROVE (COMMENTED)
...review summary...
Reviewed by: <reviewer-role>"
```

This is the fallback path that already exists in the pr-manager protocol. The proposal is to promote it from "fallback when hook fails" to "standard practice for same-account reviews" so that the PR thread always has a durable, hook-verifiable record of the review verdict.

**Connection to this issue (#651):**
#651 describes the structural unreachability of `gh pr review --approve/--request-changes` on single-identity projects. The fallback-to-comment path is the correct resolution for that class of project. This datapoint confirms the fallback path is needed in production and should be documented as the standard, not an exceptional workaround.

**User oversight note:** This instance was caught by user oversight ("did we review 617?"), not by the hook. That means the hook gap creates a situation where only the user, not the pipeline, can detect a missing review. The fallback-to-comment standard would close this gap.
