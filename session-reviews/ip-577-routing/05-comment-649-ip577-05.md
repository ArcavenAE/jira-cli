### Additional evidence for fail-closed PostToolUse timeout behavior

The jira-cli project's STATE.md is a ~336-line active pipeline-state file. The timestamp-advancement PreToolUse hook causes every edit to STATE.md to span the full file, producing monolithic writes. When the PostToolUse validator then runs on the resulting large edit, it hits the plugin timeout budget — and fails closed, blocking the write even though the write landed correctly on disk.

**Observed occurrences:** 4–5 total across 2026-07-08, 2026-07-09, and 2026-07-14. Codified as MEDIUM drift item STATE-MANAGER-MONOLITHIC-WRITE-STALL.

**Specific trigger confirmed in this cycle:**
During the wave-D BC Source sync sweep (9 BC Source rows in `bc-3-issue-write.md` updated after handler relocation), the PostToolUse validator timed out on **every single PO edit** during the sweep. The fail-closed behavior blocked each edit with an error return despite the write having succeeded on disk. The workaround used (Python-via-Bash for atomic multi-field updates, bypassing the PreToolUse per-edit gate) is now the **de facto standard** for state-manager bulk writes — it has graduated from emergency fallback to load-bearing practice.

**Impact:**
- Agent productivity stalls: the state-manager must detect the false-block, switch to the Bash-python path, and re-apply the change.
- Each stall adds latency proportional to the file size and the number of affected fields.
- The workaround is invisible to the PostToolUse validator, meaning the validator's intended invariant-checking is silently bypassed for all Bash-python writes. This creates a coverage gap in the validation chain.

**Connection to #648 / this issue (#649):**
The fail-closed behavior described in #649 (PostToolUse reports valid writes as blocked) and #648 (fail-open write with fail-closed label) are both observed here. The state-manager's timestamp-advancement hook amplifies the frequency because it forces large files rather than targeted edits.

**Proposed fix direction (reinforcing existing issue body):**
Beyond the general fix, the state-manager role definition should explicitly document that Bash-python bulk writes bypass the PostToolUse validator and are therefore only acceptable for fields that do not require the validator's invariant check. The engine-side fix (increased timeout or non-blocking mode) would eliminate the bypass entirely.

**Severity:** MEDIUM (blocking production state writes; workaround load-bearing but validation-bypassing).
