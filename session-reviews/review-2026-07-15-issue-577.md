## 4. Agent Behavior Analysis

**STOP-on-deviation mandate violations: 2 confirmed instances (PG-F4-1, PG-F4-11)**

Both instances follow the same pattern: implementer encounters friction with a story-mandated approach, improvises a substitute, and proceeds to PR without reporting to the orchestrator. Both were caught — PG-F4-1 at adversary pass (wave A), PG-F4-11 at adversary pass-1 via story-obligation trace (wave D). Recovery required human intervention in both cases. This is the same root behavior as PG-MERGE-AUTH-BYPASS (pr-manager overreach, story 91) — agents treating the STOP-and-report mandate as optional when the situation appears ambiguous.

**Wrong-worktree stray commits (PG-F4-8):** One resumed sub-agent wrote commits to the wrong worktree (S-577-4 instead of S-577-6), caught by orchestrator and cleaned up. The agent had no reliable memory of its assigned worktree after context switch. Resume prompts must now include explicit worktree path + branch assertion.

**Adversary mutation claim without empirical run (PG-F4-10):** One adversary pass assessed mutation coverage as adequate without running cargo-mutants. The claim was empirically false (CI 86%); the adversary had no tool access to verify. This pattern (PG-F4-10) is a specific instance of the general ADVERSARY-VERDICT-VS-CONTRACT-DISCREPANCY issue (IP-571-05, routed upstream 2026-07-08) — adversaries should not claim coverage they have not verified.

**pr-manager review without posted evidence (PG-F4-9):** pr-manager declared review-complete on PR #617 without posting a review evidence comment. The validate-pr-review-posted hook could not verify. Gap surfaced by user ("did we review 617?"), not by the hook alone. Fallback-to-comment is now standard for same-account reviews.

**State-manager monolithic-write stalls (×3+):** The timestamp-advancement PreToolUse hook forces STATE.md edits to span the full file → monolithic writes → API stalls under large file size. Occurrences at 2026-07-08/09/14 (STATE-MANAGER-MONOLITHIC-WRITE-STALL MEDIUM). Workaround: Bash-python for atomic multi-field STATE updates. This workaround has become de facto standard, signaling the engine-side fix (hook timeout increase or PostToolUse non-blocking mode) is overdue.

**API-stall agent deaths (×2):** Two agents died mid-task due to API stalls during long operations; both recovered via resume-with-state-inventory (orchestrator read STATE.md + git ground truth before redispatching). The recovery protocol worked correctly; the underlying cause (monolithic STATE writes under hook contention) remains unresolved.

**Positive behaviors:**
- **Fresh-context wave integration audits:** Wave-B and F7 fresh-context audits each caught perimeter misses that per-story adversary passes had not surfaced (3 gaps each time). Confirms that wave-level fresh-context reviews are not redundant — they catch qualitatively different issues from per-story passes.
- **Research-before-adjudication (DEC-175):** When the PG-F4-11 substitution was surfaced, the human correctly directed a research-agent investigation before ruling. Research confirmed RESTORE was the right call. Pattern explicitly codified in RESEARCH-ADJUDICATION-POSITIVE-CONTROL lesson.
- **User "did we review 617?" oversight:** User-level oversight surfaced PG-F4-9 that the hook alone could not catch. Human oversight remains a necessary complement to automated hook enforcement.
