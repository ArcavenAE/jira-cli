## Improvement Proposals

### Proposal 1: Initialize per-cycle cost tracking
- **Category:** cost
- **Priority:** HIGH
- **Evidence:** `.factory/cost-summary.md` missing; PERF-COST-TRACKING open; only rough ~1.2M token estimate exists for the resume-to-F7 arc; full-cycle cost unquantified.
- **Recommendation:** State-manager creates `.factory/cost-summary.md` at cycle start from a cost-summary template and updates it per phase gate. Engine-side only.
- **Affected files:** `.factory/cost-summary.md` (new), state-manager role definition, F1/F7 phase checklists.
- **Risk:** Minimal. Cost data is additive; adding tracking cannot break existing pipeline.

### Proposal 2: Mandatory F2 criterion selection at F1 gate
- **Category:** timing/convergence
- **Priority:** HIGH
- **Evidence:** DEC-158 mid-cycle escalation after 11 rounds cost ~2–3 extra passes; F2 criterion was STANDARD at start but the cycle was effectively run under STRICT without formal declaration, causing inconsistent streak counting.
- **Recommendation:** F1 gate template adds a mandatory "F2 convergence criterion" decision: STANDARD or STRICT, with an upgrade trigger condition. Selection must be committed to STATE.md at F1 gate close, before any F2 dispatch.
- **Affected files:** F1 gate template, F2 skill preamble.
- **Risk:** Low. Adds one human decision at F1 gate time; no structural change to F2 protocol.

### Proposal 3: Mandatory sibling-sweep step in F2/F3 fix-round protocol
- **Category:** convergence/template
- **Priority:** HIGH
- **Evidence:** TWIN-ARTIFACT-SWEEP ×5 this cycle (F2 ×3 + F3 ×2); each miss costs one adversary pass. Pattern has 5 confirmed recurrences.
- **Recommendation:** Add a mandatory "sibling-sweep" step to the F2/F3 fix-round checklist: before committing any spec change, grep/diff all mirroring artifacts (BC-INDEX, CANONICAL-COUNTS, spec-changelog, prd-delta manifest, story ACs) to confirm propagation.
- **Affected files:** F2 skill fix-round checklist, F3 skill fix-round checklist.
- **Risk:** Adds one grep step per fix round; low overhead; reduces adversary pass count.

### Proposal 4: Mandatory CHANGELOG task in story template
- **Category:** template
- **Priority:** MEDIUM
- **Evidence:** STORY-TEMPLATE-CHANGELOG-TASK drift item; F5-p3 MISSING-CHANGELOG-ENTRY on PR #593 (≥2nd occurrence); PR merged without CHANGELOG entry.
- **Recommendation:** Story template gains a mandatory delivery task: "Add CHANGELOG.md entry under Unreleased/[type] citing this PR." F5 adversary checklist adds CHANGELOG verification step.
- **Affected files:** Story template (engine), create-story skill, F5 adversary checklist.
- **Risk:** Low. Adding a required task cannot regress existing stories; only affects new story creation.

### Proposal 5: Mechanical adversary verdict derivation
- **Category:** agent/convergence
- **Priority:** MEDIUM
- **Evidence:** ADVERSARY-VERDICT-VS-CONTRACT-DISCREPANCY MEDIUM drift item; F5-p3 adversary declared CLEAN while reporting 1 LOW finding. Caught manually by orchestrator; uncaught would have advanced convergence counter incorrectly.
- **Recommendation:** Adversary template mandates: verdict = CLEAN iff finding count == 0; verdict = FINDINGS_PRESENT iff count > 0. Orchestrator check step added: if adversary output contains findings AND verdict = CLEAN, it is a contract violation — orchestrator must reject the pass and re-dispatch.
- **Affected files:** Adversary agent prompt/template, orchestrator convergence-check sequence.
- **Risk:** Low. Stricter mechanical check; resolves MEDIUM open drift item.

### Proposal 6: Resolve adversary write-tool mismatch
- **Category:** agent/tool
- **Priority:** LOW
- **Evidence:** ADVERSARY-WRITE-TOOL-MISMATCH drift item; F2 adversary agent has read-only tools but skill template asks it to write review files. Results in dead letter writes or skill-instruction noise.
- **Recommendation:** Adversary returns review content as text in its response; state-manager writes the file. Keeps adversary T1 read-only as designed.
- **Affected files:** Adversary agent config, F2/F3/F5 skill review-write steps.
- **Risk:** Low. Change is clarifying; no behavioral regression to adversary review quality.

### Proposal 7: Meta-lens convergence rule
- **Category:** convergence/agent
- **Priority:** HIGH
- **Evidence:** ADVERSARY-META-LENS-REGRESS; F2 passes 16–19 contributed 2–3 NITPICK/meta-process findings per pass, consuming human triage time. CITATION-GUARDS Story A had a 44-pass F3 with similar meta-lens inflation. ~3–5 passes lost per affected cycle.
- **Recommendation:** Methodology-level findings (meta-observations about the factory process itself, not about spec content) are classified INFORMATIONAL (non-resetting under all criteria) or routed to process-gap register. Under STRICT criterion, cap 2 INFORMATIONAL meta-findings per pass before routing to register. Adversary prompt gains explicit instruction.
- **Affected files:** Adversary agent prompt, STRICT convergence criterion definition.
- **Risk:** Medium. Misclassification of a legitimate spec finding as INFORMATIONAL would be a bug. Requires clear definition of "methodology-level finding" boundary.

### Proposal 8: Mandatory spec-changelog re-sync per F2 fix round
