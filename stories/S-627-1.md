# S-627-1 -- Fix check-bc-no-numeric-test-counts.sh false-positive regex + self-test seam

## Narrative

As a spec-guard CI author, I want `check-bc-no-numeric-test-counts.sh` to correctly identify
numeric test counts in BC Trace/Source fields while NOT mis-firing on structured identifiers
(CWE-NNN, BC-S.SS.NNN, #NNN issue refs, vN.N.NNN version strings), so that the guard remains
accurate and the hyphenation workarounds introduced in commit 8a0a2422 can be reverted.

## Problem Statement

The script's line-55 PATTERN matches raw digit sequences too broadly, causing false-positives on:
- `CWE-116`, `CWE-22` -- security identifiers with trailing digits
- `BC-3.8.012`, `BC-3.9.001` -- BC IDs with dotted-decimal suffixes
- `#639`, `#576` -- issue reference anchors
- `v1.3.94`, `v0.7.0` -- version strings with numeric components

To suppress these false-positives, commit 8a0a2422 applied hyphenation workarounds
(e.g., "wiremock-tests" instead of "wiremock tests") to BC Trace fields in bc-2-issue-read.md
and bc-3-issue-write.md. These workarounds make the spec prose unnatural and must be reverted
once the script is fixed. Two `[PENDING-REVERT-S-627-1]` markers in bc-3-issue-write.md
(BC-3.9.001 and BC-3.9.003 Trace fields) identify the exact revert sites.

## Source of Truth

- F1 delta analysis: `.factory/phase-f1-delta/SOH-DX-1/delta-analysis.md` section 2 (authoritative scope)
- Script source: `scripts/check-bc-no-numeric-test-counts.sh` line 55 PATTERN, line 14 BC_DIR
- Reference seam: `scripts/check-bc-citation-symbols.sh` lines 261-302 (`--self-test`/`--bc-dir` pattern to copy)
- Revert targets: `[PENDING-REVERT-S-627-1]` markers in `bc-3-issue-write.md`

## Scope

### Phase 1 (script fix PR to develop) -- THIS story's code change

1. Fix `scripts/check-bc-no-numeric-test-counts.sh` line-55 PATTERN regex:
   - Add left-boundary negative-class `[^[:alnum:].#-]` (or equivalent POSIX ERE negative lookaround workaround) before `[0-9]+`
   - Boundary must exclude digits that are part of: `CWE-NNN`, `BC-S.SS.NNN`, `#NNN` issue refs, `vN.N.NNN` version strings
   - True-positive forms ("16 wiremock tests", "3 tests", "22 test functions") MUST still trigger
   - True-negative forms (CWE-116, BC-3.9.001, #576, v1.3.94, PR-001) MUST NOT trigger

2. Add `--self-test` and `--bc-dir` CLI seam to `scripts/check-bc-no-numeric-test-counts.sh`:
   - Copy pattern from `scripts/check-bc-citation-symbols.sh` lines 261-302
   - `--bc-dir <path>`: overrides hardcoded `BC_DIR` at line 14 (BC_DIR becomes fallback default)
   - `--self-test`: runs built-in true-positive/true-negative fixture regression; exits 0 on clean, 1 on failure

3. `--self-test` fixture set (minimum required cases):
   - TRUE-POSITIVE (must trigger): "16 wiremock tests", "3 tests", "22 test functions"
   - TRUE-NEGATIVE (must NOT trigger): "CWE-116", "BC-3.9.001", "#576", "v1.3.94", "PR-001", "BC-3.8.012", "#639"

### Phase 2 (factory-artifacts revert -- AFTER Phase 1 merges to develop)

4. Revert `[PENDING-REVERT-S-627-1]` markers in `.factory/specs/prd/bc-3-issue-write.md`:
   - BC-3.9.001 Trace field: restore "wiremock tests" (remove hyphenation workaround)
   - BC-3.9.003 Trace field: restore "wiremock tests" (remove hyphenation workaround)
   - Remove `[PENDING-REVERT-S-627-1]` inline annotation from each site
   - Applies as atomic factory-artifacts commit after script fix is merged to develop

5. Revert `bc-2-issue-read.md` hyphenation workarounds (same commit 8a0a2422 set):
   - Restore "wiremock tests" (unhyphenated) in all Trace fields where the workaround was applied
