# S-626-1 -- Fix rust-toolchain SHA pins + MSRV false-green + CLAUDE.md gotcha

## Narrative

As a CI maintainer, I want:
1. All 6 workflow files to pin `dtolnay/rust-toolchain` to a verified master-ancestor SHA with
   an explicit `toolchain` input, so that the pin is both correct and self-documenting.
2. The MSRV job in ci.yml to actually validate Rust 1.85.0 (not stable), so that the
   minimum-supported-rust-version claim is enforced rather than silently passing on any stable version.
3. A CLAUDE.md gotcha note documenting the `rust-toolchain.toml` vs `RUSTUP_TOOLCHAIN` precedence
   resolution, so future contributors understand why the env override is necessary.

## Problem Statement

**Defect 1 -- Stale SHA pin (6 workflow files):**
All 6 workflow files currently pin `dtolnay/rust-toolchain@c93f4f9c67595668add93d3d6895795ce52d8c2d`.
This SHA is NOT a master ancestor of the dtolnay/rust-toolchain repository. It is a per-version-branch
commit (expected behavior for that repo's branch structure) -- not evidence of compromise, but
not a reliable master-track pin either. The replacement `fa04a1451ff1842e2626ccb99004d0195b455a88`
was confirmed as a master ancestor at F2 (P71-001, DISCHARGED).

**Defect 2 -- MSRV false-green (ci.yml msrv job):**
The msrv job uses `dtolnay/rust-toolchain@<SHA>` WITHOUT a `with: {toolchain: "1.85.0"}` input.
The action then reads `rust-toolchain.toml` which has `channel = "stable"`. Result: the msrv job
installs and validates `stable`, not `1.85.0`. The job is silently green even if the codebase
uses features introduced after 1.85.0.

Fix: add `with: {toolchain: "1.85.0"}` input to the msrv job's action step AND add
`env: {RUSTUP_TOOLCHAIN: "1.85.0"}` to the `cargo check` step. The `RUSTUP_TOOLCHAIN` env
variable outranks `rust-toolchain.toml` at the process level (see CLAUDE.md gotcha note).

**Defect 3 -- Missing CLAUDE.md gotcha:**
No documentation exists explaining why `RUSTUP_TOOLCHAIN` is needed instead of relying on
`dtolnay/rust-toolchain`'s `toolchain` input alone. The gotcha must be added so future
contributors do not regress this.
