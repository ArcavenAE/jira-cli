# S-SOH-590-1: case-insensitive HTTP method on `jr api -X`

**Bundle**: SOH-BUGS-1
**GitHub issues**: #590 (bug report), #582 (feature request — same root cause)
**BC anchors**: none blocking; BC-X.1.011 planned post-fix (optional, PO-owned)
**VP**: VP-590-001 (planned — DELETE/delete/Delete all → HttpMethod::Delete → HTTP DELETE dispatched)
**Routing**: quick-dev (F1 TRIVIAL)

---

## Narrative

- **As a** developer or AI agent calling Jira REST endpoints via `jr api`
- **I want** `jr api -X DELETE /path` (and uppercase variants of all HTTP methods) to be accepted
- **So that** `jr api` follows the established `curl -X` / `gh api -X` convention where uppercase
  method strings are the idiomatic form, eliminating clap parse errors that block normal usage

---

## Problem

`jr api -X DELETE /path` fails with a clap parse error before any I/O occurs:

```
error: invalid value 'DELETE' for '--method <METHOD>'
  [possible values: get, post, put, patch, delete]
```

clap 4.x `ValueEnum` matching is case-sensitive by default. `HttpMethod` variants derive as
`get`/`post`/`put`/`patch`/`delete` (lowercase kebab-case). Both `curl -X DELETE` and
`gh api -X DELETE` use uppercase by convention; the deviation surprises users following
standard tooling muscle memory. Workaround exists (`-X delete` lowercase works), but it
is a UX regression relative to peer tools. Issues #590 (bug form) and #582 (feature form)
describe the same root cause and close with the identical one-line fix.

---

## Solution

Add `ignore_case = true` to the `-X / --method` `#[arg]` annotation in `src/cli/mod.rs`
at line 127. This is a purely additive attribute — the `HttpMethod` enum variants, the
`From<HttpMethod> for Method` impl, and the lowercase possible-values help text are all
unchanged. `ignore_case = true` is a standard clap 4.x `#[arg]` attribute.

```rust
// src/cli/mod.rs — the ONLY change
#[arg(short = 'X', long, value_enum, ignore_case = true, default_value_t = api::HttpMethod::Get)]
method: api::HttpMethod,
```

## Architecture Compliance Rules

(Extracted from `src/cli/api.rs`, `src/cli/mod.rs`, and ADR-0001)

1. **`ignore_case` on `#[arg]`, never on the enum.** The `HttpMethod` enum definition
   (`src/cli/api.rs:16`) MUST NOT be modified. `ignore_case = true` is a clap parse-time
   attribute; it does not affect the enum's runtime representation or serialisation.

2. **No new CLI surface.** This fix adds no new flags, subcommands, or output fields.
   `tests/e2e_cli_surface_guard.rs` must stay green without modification.

3. **Forbidden dependency introduction.** `src/cli/mod.rs` MUST NOT gain any new `use`
   imports for this change. The `api::HttpMethod` reference is already present.

4. **Lowercase help text invariant.** clap renders `[possible values: ...]` from the enum
   variant names, not from user input. `ignore_case = true` does not change the help text.
   If help text changes are observed, the implementation is wrong.

5. **`From<HttpMethod> for Method` unchanged.** The dispatch path (enum → reqwest::Method)
   is correct for all variants. The case-insensitivity fix is purely at the clap parse
   boundary; `HttpMethod` values passed downstream are always canonical enum variants.
