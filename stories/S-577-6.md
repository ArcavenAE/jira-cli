### AC-007: adf_to_text failure → exit 64 (EC-3.5.010-2a) — two-tier test
(traces to BC-3.5.010 EC-3.5.010-2 — adf_to_text error propagates as exit 64)

**NOTE: the >256-deep wiremock fixture approach is unproducible.** A ≥129-deep JSON body
is rejected by `serde_json::from_slice` (serde default recursion limit = 128; called in
`client.rs::get`, ~265) before `adf_to_text` is called — resulting in `JrError::Json` →
exit 1, NOT exit 64. The `adf_to_text` depth-guard exit-64 path is therefore unreachable
via the HTTP/wiremock boundary. This is an implementation fact, NOT a spec contradiction:
EC-3.5.010-2(a) is a PROPAGATION contract ("a UserError from `adf_to_text` propagates
unchanged") — the exit-64 class must be testable, but not necessarily through a subprocess
wiremock fixture.

Two-tier test strategy:

**(i) UNIT-LEVEL propagation test (mandatory):** Programmatically BUILD (not parse —
construction has no serde 128-limit) a `serde_json::Value` ADF node with nesting depth
> 256, entirely in-process. Call `adf_to_text(&deep_node)` directly (or the
`render_comment_view` helper if extracted as a testable unit). Assert the call returns
`Err(...)` with the depth-guard error, and that the handler maps it to the
`UserError`/exit-64 class. This test lives in the lib/unit tier — either as an inline
`#[test]` in `src/cli/issue/interactions.rs` or as a test helper that bypasses the HTTP
parse path entirely. Cross-reference: `tests/adf_recursion_depth.rs` uses the same
programmatic BUILD approach for the forward path (e.g.,
`test_markdown_to_adf_depth_256_blockquote_is_err`). `MAX_ADF_DEPTH` is `pub(crate)` —
inaccessible from `tests/` integration tests (CLAUDE.md: "The constant regression pin
lives in `src/adf.rs::test_max_adf_depth_constant_is_256`"). Use programmatic
construction, not a constant reference.

**(ii) BOUNDARY-BEHAVIOR note + optional subprocess assertion:** A response body with
≥129-deep JSON nesting is rejected at deserialization → `JrError::Json` → exit 1 at the
CLI boundary. This is the observable actual behavior via wiremock. Optionally pin it with
a subprocess test in `tests/comment_view.rs` asserting exit 1 on a 129-deep fixture —
label it clearly as testing the JSON-parse-error path, NOT the `adf_to_text` path.

**Implementation note recorded for posterity:** adf_to_text's sole error kind is
unreachable via wiremock on the view path (serde 128-parse limit fires first) — this
is an implementation fact, not a spec contradiction; EC-3.5.010-2(a) is pinned at
unit level per tier (i) above.

**Tests**:
- `test_bc_3_5_010_ec2a_adf_error_propagates_exit64` (unit-level, lib tier) — tier (i)
- `test_bc_3_5_010_ec2a_deep_json_parse_error_exits_1` (optional subprocess, `tests/comment_view.rs`) — tier (ii)

### GET Request URL

`GET /rest/api/3/issue/{urlencoded_key}/comment/{urlencoded_id}?expand=properties`

The issue key is URL-encoded in the path (per `get_comment` in S-577-2); the `--id` value, once validated by `validate_comment_id`, needs no further encoding (EC-3.5.002-2). The `?expand=properties`
query parameter is REQUIRED — without it, the `properties` array (which carries the
`sd.public.comment` internal flag) is absent from the response.

The `get_comment` method in S-577-2 already includes `?expand=properties`.

### 7-Element Human Render Format (6 labeled fields + unlabeled body block)

```
ID: 10001
Author: Jane Smith
Created: 2026-07-01T09:00:00.000+0000
Updated: 2026-07-01T10:30:00.000+0000
JSM internal: Yes
Restricted: Software Engineers

The comment body text here, rendered from ADF via adf_to_text.
Wrapped at terminal width if long.
```

Key formatting rules:
- **Plain key-value lines**: `<Label>: <value>` with single space after colon, LF terminator.
  NOT comfy-table. NOT column-aligned padding.
- Fields 1–6: `<Label>: <value>` — one space after the colon, no manual tab stops.
- Body block (unlabeled, field 7): body text rendered via `adf_to_text`, appears below a blank-line separator after field 6; no `"Body:"` label emitted.
- Timestamps (fields 3/4): Render the raw ISO 8601 value as returned by Jira's API; do NOT reformat.

### 4-Rung Restricted Ladder (pure helper)

```rust
fn format_restricted_field(visibility: Option<&serde_json::Value>) -> String {
    match visibility {
        None => "None".to_string(),
        Some(v) => {
            let vtype = v["type"].as_str().unwrap_or("");
            let value = v["value"].as_str().unwrap_or("");
            let identifier = v["identifier"].as_str().unwrap_or("");
            match (vtype, value.is_empty(), identifier.is_empty()) {
                // Rung (a): role/group with non-empty value
                ("role" | "group", false, _) => value.to_string(),
                // Rung (b): role/group with empty value, non-empty identifier
                ("role" | "group", true, false) => format!("id={}", identifier),
                // Rung (c): non-role/group type — value-OR-identifier preference:
                //   non-empty value → "<type>:<value>"
                //   empty value + non-empty identifier → "<type>:<identifier>"
                //   (never emit "None" for a known non-role type with an identifier present)
                (t, _, _) if !t.is_empty() && !value.is_empty() => format!("{}:{}", t, value),
                (t, _, false) if !t.is_empty() => format!("{}:{}", t, identifier),
                // Rung (d): fallback
                _ => "None".to_string(),
            }
        }
    }
}
```

The `visibility` field comes from `response["visibility"]` (a `serde_json::Value`).

### JSM Internal Field Resolution

```rust
fn format_jsm_internal_field(properties: Option<&serde_json::Value>) -> &'static str {
    // properties is an array of {key, value} objects
    let props = match properties.and_then(|v| v.as_array()) {
        Some(arr) => arr,
        None => return "N/A",
    };
    for prop in props {
        if prop["key"].as_str() == Some("sd.public.comment") {
            return match prop["value"]["internal"].as_bool() {
                Some(true) => "Yes",
                Some(false) => "No",
                None => "N/A",
            };
        }
    }
    "N/A"
}
```

### serde_json::Value Passthrough

`get_comment` returns `serde_json::Value` (NOT a typed `Comment` struct). This is
deliberate — typed structs drop unknown fields silently (the MERGE/PRESERVED research
showed Jira returns additional fields). For `--output json`, pass the `Value` directly
to `output::render_json`. Do NOT deserialize to a typed struct and re-serialize.

### Forbidden Dependencies

`interactions.rs` MUST NOT use `serde_json::to_string_pretty` directly. All JSON output
routes through `output::render_json`.

## Architecture Compliance Rules

(Extracted from CLAUDE.md, BC-3.5.010)

1. **`serde_json::Value` passthrough — NOT typed struct.** `get_comment` returns `Value`.
   For `--output json`, pass the `Value` directly to `render_json`. Do NOT deserialize
   to a typed `Comment` struct — that silently drops unknown fields (MERGE/PRESERVED
   research confirmed Jira returns additional fields).

2. **`?expand=properties` is REQUIRED on the GET.** Without it, the `properties` array
   is absent and Field-5 (JSM internal) always shows N/A regardless of actual visibility.
   Already enforced in S-577-2's `get_comment` implementation; do not strip the query param.

3. **`adf_to_text` errors are exit 64 (NOT exit 1).** EC-3.5.010-2(a): `adf_to_text`
   returns `JrError::UserError` on malformed ADF. Propagate with `?` — the error's
   exit code is 64. Do NOT silently substitute placeholder text.

4. **4-rung Restricted ladder order is non-negotiable.** Rung (a) > (b) > (c) > (d).
   Rungs (a) and (b) both require `type == "role" || type == "group"`. Check (a) before
   (b) — non-empty value wins over non-empty identifier. Rung (c) handles non-role types.
   Rung (d) is the catch-all.

5. **JSON output invariant (#526).** All JSON routes through `output::render_json`.
   No direct `serde_json::to_string_pretty` calls.

6. **Blank-line separator on body block.** Body text appears after a blank-line separator
   following the `Restricted:` field-6 header; no `"Body:"` label is emitted. This
   separator is load-bearing for VP-577-021 variant 1.
