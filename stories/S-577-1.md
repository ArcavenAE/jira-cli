## Narrative

- **As a** developer using `jr` to manage Jira comments
- **I want** `jr issue comment` to be a subcommand group with `add`, `delete`, `edit`,
  and `view` subcommands
- **So that** the new delete/edit/view operations introduced in #577 have a coherent,
  discoverable CLI surface, and the old flat form is replaced with a clear migration hint

---

## Problem

`IssueCommand::Comment` is currently a leaf variant (positional `message` argument).
Adding `delete`, `edit`, and `view` operations requires converting `Comment` into a
subcommand group. The old flat form `jr issue comment KEY "text"` cannot coexist with
nested subcommands in clap without an explicit external-subcommand fallback — it must
be removed and replaced with `jr issue comment add KEY "text"` with a migration hint.

`workflow.rs` is currently 1,341 LOC (34% over the ADR-0012 1,000-LOC threshold, PF-017).
Adding three new handlers without extraction would push it to ~1,600 LOC. This story
triggers the planned PF-017 shard: extract `handle_comment` → `handle_comment_add` into
a new `src/cli/issue/interactions.rs`; stub `handle_comment_delete/edit/view` as `todo!()`.

### Error-Intercept Architecture

```
try_parse() error → match err.kind():
  InvalidSubcommand under "comment" → inspect context() for attempted token:
    "list" | "ls" (case-insensitive) → emit "jr issue comments" hint
    _ (incl. flat KEY form)          → emit "use `jr issue comment add` instead"
  _ (any other clap ErrorKind)       → pass through unmodified (byte-identical)
```

The sub-case token discrimination MUST walk `err.context()` — NOT argv positional
scanning, which breaks under global-flag reordering (e.g., `jr --output json issue comment KEY`).

### Forbidden Dependencies

`src/cli/issue/interactions.rs` MUST NOT gain a dependency on `src/cli/issue/edit.rs`
or `src/cli/issue/create.rs`. It imports from `workflow.rs` only for `pub(super)` helpers
(`refuse_noninteractive`, dialoguer-related utilities) and from `api/jira/issues.rs`.

### Task 2 — Create CommentSubcommand enum in src/cli/mod.rs

Add the `CommentSubcommand` enum after `IssueCommand`. The `Add` variant carries all
existing fields from `IssueCommand::Comment`. The `Delete`, `Edit`, `View` variants carry
`key: String` plus `id: String` (with `#[arg(long)]`) plus operation-specific flags.
Change `IssueCommand::Comment` from a leaf struct variant to `Comment(CommentSubcommand)`.

```rust
#[derive(Subcommand, Debug, Clone)]
pub enum CommentSubcommand {
    /// Add a comment (canonical form; replaces the old flat `jr issue comment KEY text`)
    Add {
        key: String,
        #[arg(allow_hyphen_values = true)]
        message: Option<String>,
        #[arg(long)] markdown: bool,
        #[arg(long)] file: Option<String>,
        #[arg(long)] stdin: bool,
        #[arg(long)] internal: bool,
    },
    /// Delete a comment by ID — requires --yes or interactive confirmation
    Delete {
        key: String,
        #[arg(long)] id: String,
        #[arg(long)] yes: bool,
    },
    /// Edit a comment body (optionally set visibility)
    Edit {
        key: String,
        #[arg(allow_hyphen_values = true, conflicts_with_all = &["file", "stdin"])]
        text: Option<String>,
        #[arg(long)] id: String,
        #[arg(long, conflicts_with_all = &["stdin", "text"])] file: Option<String>,
        #[arg(long, conflicts_with_all = &["file", "text"])] stdin: bool,
        #[arg(long)] markdown: bool,
        #[arg(long, conflicts_with = "public")] internal: bool,
        #[arg(long, conflicts_with = "internal")] public: bool,
        #[arg(long)] yes: bool,
    },
    /// View a single comment by ID
    View {
        key: String,
        #[arg(long)] id: String,
    },
}
```

Help text for `jr issue comment` SHOULD mention: "to list all comments, use `jr issue comments`".

## Architecture Compliance Rules

(Extracted from `src/cli/mod.rs`, `src/cli/issue/mod.rs`, CLAUDE.md, ADR-0012)

1. **All free-text positional args carry `allow_hyphen_values = true`.** `CommentSubcommand::Add`
   positional `message` and `CommentSubcommand::Edit` positional `text` MUST both carry
   `#[arg(allow_hyphen_values = true)]` per CLAUDE.md invariant.

2. **No clap `requires` on `--yes`.** EC-3.5.008-4 requires `--yes` be accepted silently on
   non-`--public` paths. Do NOT apply `#[arg(requires = "public")]` to `yes` in Edit.

3. **`conflicts_with` enforces `--internal` / `--public` mutual exclusion** on
   CommentSubcommand::Edit (BC-3.5.011).

4. **try_parse intercept is scoped to InvalidSubcommand only.** All other clap ErrorKinds
   pass through byte-identically. Do NOT intercept `MissingRequiredArgument` or similar.

5. **interactions.rs uses `pub(super)` visibility** — not `pub`. Handlers are invoked only
   from `src/cli/issue/mod.rs` (the parent module).

6. **workflow.rs retains all non-comment handlers.** `handle_open`, `handle_move`,
   `handle_assign`, and all other handlers STAY in workflow.rs. Only `handle_comment` is
   extracted. `handle_open` extraction is explicitly OUT of scope for this story.

7. **No new CLI surface beyond spec.** The four subcommands (add/delete/edit/view) are the
   only new CLI paths. No `--output json` default changes.
