### AC-005 (traces to BC-X.8.010 postcondition: SEC-576-006 stale-ID self-heal; invalidate + retry once)

SEC-576-006 stale-ID self-heal: fires when the **step-1** POST (`POST .../attachTemporaryFile`) returns 404 or 403 using a cached `sdId` (BC-3.9.003 step 1; P30-001). Does NOT fire on step-2 failures (those map to BC-3.9.006 failure taxonomy):

1. Invalidate the `project_meta.json` cache entry for `(profile, projectKey)` (delete or mark stale).
2. Re-call `get_or_fetch_project_meta` with a fresh HTTP fetch (cache-miss path: `GET /rest/api/3/project/{key}` + paginated `GET /rest/servicedeskapi/servicedesk`).
3. Re-run step 1 with the re-resolved `sdId`.
4. On second failure: post-retry 404 → exit 64 (`"Service desk for <projectKey> not found after refresh."`); post-retry 403 → exit 1 (permission denied); post-retry 401 → exit 2 (not authenticated); post-retry 5xx/network error → exit 1. Do NOT retry again.

This handles the case where a JSM service desk was reconfigured and the cached `sdId` is stale. The single-attempt retry is load-bearing — do NOT loop.
