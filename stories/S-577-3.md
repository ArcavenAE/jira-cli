### Deletion Pipeline Order (BC-3.5.003 delete-pipeline ordering pin)

```
(1) --id regex validation (EC-3.5.002-1): validate_comment_id(id) → exit 64 on mismatch
(2) Confirmation gate (BC-3.5.003):
      if no_input && !yes → exit 64 + "Use --yes to confirm"  (test cli.no_input ONLY)
      if yes → skip prompt
      else → y/N prompt via dialoguer::Confirm::interact_on(&Term::stderr())
(3) HTTP DELETE (client.delete_comment(key, id).await)
    204 → success output
    404/403 → exit 64 + two-line stderr body surface (BC-3.5.004)
    other 4xx/5xx (except 401) → ApiError exit 1
    401 → auth framework exit 2
```

### JR_STDIN_IS_TTY Seam Implementation

In `src/main.rs`, at the `if !cli.no_input { ... }` block (~line 55):

```rust
if !cli.no_input {
    use std::io::IsTerminal;
    let oauth_code_test_mode = std::env::var("JR_OAUTH_CODE").is_ok();
    #[cfg(debug_assertions)]
    let stdin_is_tty_forced = std::env::var("JR_STDIN_IS_TTY")
        .map(|v| v == "1")
        .unwrap_or(false);
    #[cfg(not(debug_assertions))]
    let stdin_is_tty_forced = false;
    if !stdin_is_tty_forced && !std::io::stdin().is_terminal() && !oauth_code_test_mode {
        cli.no_input = true;
    }
}
```

The seam gates ONLY this block. `interact_on(&Term::stderr())` is used unconditionally
for ALL dialoguer calls in all builds (not gated by this seam — required in all builds
to write the prompt to stderr while reading from stdin).

### Shared --id Validation Helper

```rust
/// Validates a comment ID argument per EC-3.5.002-1.
/// Accepts IDs matching `^[0-9A-Za-z_-]+$`; returns Err(JrError::UserError) on mismatch.
fn validate_comment_id(id: &str) -> Result<()> {
    if id.is_empty() || !id.chars().all(|c| c.is_ascii_alphanumeric() || c == '_' || c == '-') {
        return Err(JrError::UserError(format!("invalid comment id: {}", id)).into());
    }
    Ok(())
}
```

This helper is used by all three handlers (delete, edit, view). Define it once in
`interactions.rs` as a private function; re-use by name in each handler.

No `regex` or `once_cell` crate is needed — the pattern `^[0-9A-Za-z_-]+$` is
fully covered by `is_ascii_alphanumeric() || c == '_' || c == '-'` with an
explicit empty-string guard.

### Task 3 — Create tests/jr_stdin_is_tty_release_gate.rs (AC-007)

Mirror `tests/base_url_release_gate.rs` structure — use the ADJACENCY-WINDOW approach (not
bare presence checks). The two-independent-presence-check pattern cannot fail on the

```rust
#[test]
fn test_jr_stdin_is_tty_cfg_gate_present_in_main_source() {
    let src = include_str!("../src/main.rs");
    let lines: Vec<&str> = src.lines().collect();

    let env_read_line = lines
        .iter()
        .position(|l| l.contains("JR_STDIN_IS_TTY") && l.contains("std::env::var"))
        .expect(
            "Could not locate the JR_STDIN_IS_TTY env-var read in src/main.rs. \
             Has the code been moved? Update this test if the location changed.",
        );

    let window_start = env_read_line.saturating_sub(5);
    let window = &lines[window_start..=env_read_line];
    let gate_present = window
        .iter()
        .any(|l| l.contains("#[cfg(debug_assertions)]"));

    assert!(
        gate_present,
        "JR_STDIN_IS_TTY VIOLATION: `#[cfg(debug_assertions)]` not found within 5 lines \
         of the `JR_STDIN_IS_TTY` env-var read at line {} of src/main.rs.\n\
         The env-var read MUST be gated so it is excluded from release binaries.\n\
         Relevant source window:\n{}",
        env_read_line + 1,
        window.join("\n")
    );
}
```

## Architecture Compliance Rules

(Extracted from CLAUDE.md, BC-3.5.003, BC-3.5.006 delivery obligation)

1. **`interact_on(&Term::stderr())` is unconditional (all builds) and NEWLY INTRODUCED.**
   This bundle is the first src/ site to use `interact_on(&Term::stderr())` — there is no
   existing precedent to copy from. The spec (BC-3.5.003 delivery obligation) requires it so
   prompts are written to stderr (not /dev/tty). Do NOT put this inside a
   `#[cfg(debug_assertions)]` block. The seam gates ONLY the auto-`--no-input` flip.

2. **`dialoguer::Error` → `JrError::Interrupted` (exit 130).** MUST NOT be silently
   swallowed or mapped to the cancel path (exit 0). EC-3.5.003-3 is a load-bearing
   safety requirement.

3. **Delete pipeline ORDER is non-negotiable.** Steps 1 (id validation) → 2 (confirmation)
   → 3 (HTTP DELETE). No reordering allowed.

4. **404 is NOT idempotent.** DEC-168 ruling 3 overrides the F1 draft proposal. 404 →
   exit 64 + two-line stderr body surface. Do NOT treat 404 as success.

5. **`JR_STDIN_IS_TTY` release gate is mandatory.** The seam MUST ship with its
   `tests/jr_stdin_is_tty_release_gate.rs` gate test in the SAME commit. No exceptions.

6. **`JR_STDIN_IS_TTY` CLAUDE.md entry mandatory.** Per doc-fallout rule: every new
   `JR_*` env var requires a CLAUDE.md doc line in the same PR.

7. **JSON cancel envelope: `id` and `key` ABSENT.** EC-3.5.003-2 cancel path:
   `{"cancelled":true,"deleted":false}` — exactly 2 keys. `id`/`key` must NOT appear
   because no HTTP call confirmed them server-side.

8. **WARNING: Do NOT call `is_terminal()` inside the handler.** The handler MUST test
   `no_input` ALONE for the confirmation gate — NOT re-derive `is_terminal(&stdin())` or
   call `refuse_noninteractive(no_input, is_terminal(&stdin()))`. Re-deriving TTY state at
   handler call time defeats the `JR_STDIN_IS_TTY` seam (which only gates the `src/main.rs`
   auto-`--no-input` flip). See the `handle_move` call site (`workflow.rs:~660`) for the
   pattern to avoid: the CALLER derives TTY via `is_terminal(&stdin())` and passes it in —
   do NOT replicate that derivation at the comment-handler call sites, as it breaks AC-004
   and AC-009 when `JR_STDIN_IS_TTY=1` is set with piped stdin. Use
   `if no_input && !yes { return Err(…) }` directly.
