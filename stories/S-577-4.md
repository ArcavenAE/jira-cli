## Narrative

- **As a** developer managing Jira comments from the CLI
- **I want** `jr issue comment edit KEY --id ID [BODY | --file F | --stdin | --markdown]` to
  update a comment's body using a simple PUT call
- **So that** I can correct or update comment content precisely, knowing the API call only
  modifies the body text and never touches visibility properties

### Edit Pipeline Order (BC-3.5.009 edit-pipeline ordering pin)

```
(1) --id regex validation (EC-3.5.002-1): validate_comment_id(id) → exit 64 on mismatch
(2) Body source resolution (BC-3.5.009):
      --file  → fs::read_to_string(path) — explicit error: file not found → exit 64 (EC-3.5.009-1)
      --stdin → std::io::Read::read_to_string from stdin
      positional BODY → use as-is
      else (no source) → exit 64: "body is required — use --file, --stdin, or pass text as a positional argument."
      (--markdown is a modifier: applies markdown_to_adf conversion to selected body source)
(3) Empty/whitespace guard (EC-3.5.009-5): body.trim().is_empty() → exit 64
(4) ADF conversion: let trimmed = body.trim().to_string(); text_to_adf(&trimmed) or markdown_to_adf(&trimmed) depending on --markdown
    (trim-then-ADF per BC-3.5.005 ~2295; raw pre-trim body already stashed in step 2 for changed_fields.body)
(5) HTTP PUT: client.update_comment(key, id, adf_body, None).await
    (None = body-only; this story implements the default no-visibility-flag path)
    200 → success output
    404/403 → exit 64 + body surface
    other 4xx/5xx (except 401) → exit 1
    401 → exit 2
(6) Output: --output json → stdout JSON; human → stderr success message
```

### Body-only PUT wire format (BC-3.5.005 body invariant)

The `update_comment` API method (from S-577-2) accepts a single `visibility_flag: Option<bool>`
parameter. When `None` (this story's scope), the implementation MUST produce a PUT request
body of:

```json
{"body": <adf_value>}
```

The `"properties"` key MUST NOT be present in the request when neither `--internal` nor
`--public` is passed. This is the body-only invariant (EC-3.5.005-1, DEC-168 ruling 1).

Validated by AC-003 (wire-level inspection of PUT request body).

### Response JSON format (BC-3.5.005 output shape)

On 200 success with `--output json`:

```json
{
  "changed_fields": {
    "body": "<raw pre-trim user input>"
  },
  "id": "<comment id>",
  "key": "<issue key>",
  "updated": true
}
```

`changed_fields.body` is the raw user-supplied input string (pre-trim), NOT the
ADF-converted value and NOT `"(updated)"`. This mirrors the `issue edit --description`
asymmetry documented in CLAUDE.md §"issue edit description echo asymmetry (issue #398)".

### Forbidden Dependencies

`interactions.rs` must NOT import `serde_json::to_string_pretty` directly. All JSON
output MUST route through `output::render_json` or `output::print_output`. No compact
JSON printing allowed (JSON render invariant #526 in CLAUDE.md).

## Architecture Compliance Rules

(Extracted from CLAUDE.md, BC-3.5.005, BC-3.5.009)

1. **Body-only PUT invariant (EC-3.5.005-1):** When neither `--internal` nor `--public`
   is passed, the PUT request body MUST contain only the `"body"` key. No `"properties"`
   key. This is load-bearing — a MERGE semantics footgun (see S-577-5 for the CLAUDE.md
   gotcha note). Validated by wire-level inspection (AC-003).

2. **`changed_fields.body` is raw pre-trim input.** Store the raw input string BEFORE
   any trim or ADF conversion. Do NOT echo the ADF value or `"(updated)"` in the JSON
   channel. The human channel may say `"(updated)"` — the JSON channel MUST be lossless.

3. **EC-3.5.009-1: file not found is exit 64, NOT exit 1.** Use explicit error matching on
   `e.kind() == std::io::ErrorKind::NotFound` for the UserError remap; propagate other IO
   errors (permission-denied, is-a-directory, etc.) unchanged via `?`. EC-3.5.009-1 scopes
   the "file not found" UserError to `NotFound` only — a blanket `map_err(|_| …)` would
   incorrectly swallow permission-denied as "file not found". Deliberate deviation from
   add_comment file handling.

4. **JSON output invariant (#526):** ALL JSON must route through `output::render_json`.
   No `serde_json::to_string_pretty` calls, no compact prints.

5. **Pipeline ORDER is non-negotiable.** Steps (1) id validation → (2) body source →
   (3) empty guard → (4) ADF → (5) HTTP PUT → (6) output. No reordering.

6. **`--markdown` is a modifier, not a source.** It applies to whichever body source is
   selected. `--markdown` + `--file` is allowed (converts file content via markdown_to_adf).
   `--markdown` + `--stdin` is allowed. `--markdown` + positional is allowed.
