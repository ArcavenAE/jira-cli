# S-640-1 -- Raise declared MSRV 1.85→1.88 + fix collapsible_if + unpin comfy-table

## Narrative

As a CI maintainer, I want to raise the declared minimum-supported Rust version from 1.85 to 1.88
so that `Cargo.toml`, `README.md`, and the MSRV CI job all reflect the genuine minimum after
`comfy-table` is unpinned, and so that contributors on older toolchains receive a clear compile
error rather than a silent failure.

**Prerequisite:** S-626-1 must be merged before this story is started. S-626-1 pins
`comfy-table = "=7.2.1"` as a temporary workaround to keep the declared MSRV of 1.85 genuine.
This story un-does that workaround by raising the MSRV properly and removing the pin.

**Why this is a separate story:** Raising the declared MSRV from 1.85 to 1.88 activates 49
`collapsible_if` clippy warnings across 27 `src/` files (clippy is MSRV-aware; at 1.88 it now
proposes let-chain constructs). Project policy forbids `#[allow]` suppression — every warning
must be resolved by refactoring. Touching 27 `src/` files changes the risk profile relative to
S-626-1 (which was CI-only) and warrants dedicated, planned scope.

## Problem Statement

**Deferred from S-626-1 v1.1 (human ruling 2026-07-30):** S-626-1 fixed the MSRV CI job to
validate Rust 1.85.0 instead of stable. On the first real run it surfaced that `comfy-table 7.2.2`
requires Rust ≥1.88.0 (let-chains, edition 2024). An amendment raised the declared MSRV to 1.88,
but that triggered 49 `collapsible_if` clippy errors across 27 `src/` files — a 27-file refactor
that deserves its own reviewed delivery. S-626-1 pins `comfy-table = "=7.2.1"` as a load-bearing
workaround to keep MSRV 1.85 genuine. This story removes the workaround by raising MSRV correctly.

**Open question for planning (decide before elaborating ACs):**
`docs/superpowers/specs/2026-03-21-jr-jira-cli-design.md` ~:616 and ~:658 state the MSRV policy
as "1.85.0 (or latest stable minus 3 releases)". With stable at 1.96, the formula implies ~1.93.
The stated formula and the pinned number have drifted. Decide: update the formula, the number, or
remove the formula before locking AC scope.

`cargo clippy -- -D warnings` exits clean on Rust 1.88.0 across all 27 affected `src/` files.
No `#[allow(clippy::collapsible_if)]` annotations added (project policy). Refactors are mechanical
(nested `if a { if let Some(x) = b { … } }` → `if a && let Some(x) = b { … }`) but every changed
hunk must be reviewed.

### AC-3 (draft): comfy-table unpinned back to caret range

`comfy-table` dependency in `Cargo.toml` changed from exact pin `"=7.2.1"` back to a caret range
(e.g., `"^7"` or `"^7.2"`). `Cargo.lock` resolves to `comfy-table 7.2.2` or later.

### AC-4 (draft): cargo test --all-features green

All tests pass on Rust 1.88.0 after the refactors. The collapsible_if changes are mechanical
but must not inadvertently alter behavior.

### AC-5 (draft): CHANGELOG.md entry

User impact: source builds on Rust 1.85–1.87 will fail. Prebuilt binary users are unaffected.
